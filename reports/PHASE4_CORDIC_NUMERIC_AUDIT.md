# Phase 4 pre-edit numeric audit of the verified baseline

This audit was written before any Phase 4 RTL change. Phase 3 Git checkpoint was `ab1596c` with a clean tree. The inspected source is `rtl/baseline/canny_get_grandient.v`, `cordic_sqrt.v`, `cordic_pipline.v`, `canny_nonLocalMaxValue.v`, `canny_edge_detect_top.v`, and the unchanged line-buffer modules. No `rtl/baseline` or `rtl/phase3` file is to be edited.

## Sobel and legal range

`canny_get_grandient.v:96-109` states and `:111-149` implements, on 3×3 pixels `p11..p33`, `Gx_signed=(p11+2p21+p31)-(p13+2p23+p33)` and `Gy_signed=(p11+2p12+p13)-(p31+2p32+p33)`. Here x is positive to the image left and y is positive toward the image top (both signs are reversed relative to right/down coordinates). Each weighted side is at most `255+2·255+255=1020`, so each signed component lies in `[-1020,1020]` and each absolute component in `[0,1020]`. The exact maximum Euclidean magnitude is `sqrt(1020²+1020²)=1442.497833...`, so the rounded/truncated integer result needs **11 unsigned bits**. The old stage stores unsigned absolute `Gx/Gy` in 11 bits and separate sign bits (`:136-149`), but later reduces magnitude to 10 bits.

## Existing CORDIC path and failure mechanisms

`canny_get_grandient.v:170-182` instantiates `cordic_sqrt` with 11-bit inputs, formal 22-bit output, and `Pipeline=9`; the connected `sqrt_out_n` is only 16 bits (`:34-40`). XELAB and synthesis report the 22→16 port mismatch (`reports/phase3_xelab.log:8`; `reports/phase3_synth_runme.log:100`). `cordic_sqrt.v:36-40` stores coordinates as signed 11-bit arrays. The vectoring CORDIC's maximum scaled coordinate is about `K_gain·sqrt(1020²+1020²) = 1.646760258·1442.497833 ≈ 2375.4`, requiring **13 signed bits minimum** even before guard/fractional precision. For `(1020,1020)`, stage 0 computes `x'=2040`, already above signed-11 maximum 1023 (`cordic_pipline.v:30-43`); the old result wraps.

The old source instantiates **16** stages (`cordic_sqrt.v:42-57`) but, for `Pipeline=9`, the magnitude taps `x[Pipeline-1]=x[8]`, after stage 7, whereas angle taps `rot_out[Pipeline-1]=rot_out[8]`, after stage 8 (`cordic_sqrt.v:59-60`). The magnitude and angle therefore come from different vectoring iterations **and different input pixels** in the pipelined stream. Both calculations use a 32-bit degree×2¹⁶ angle accumulator and nonzero Q16 arctangent constants through stage 15 (`cordic_sqrt.v:16-31`); the published constants are approximate, not mathematically exact. The gain correction is `K=0x09b74` (39796 in Q16) multiplied before `>>16` (`:33,59`). `angle_out` is only the high integer-degree part `[6:0]` (`:11,60`), discarding the later fractional-angle resolution. `cordic_pipline.v:11` declares a 6-bit `pipline_level`, but all 16 instantiations pass unsized integer literals (`cordic_sqrt.v:42-57`), producing XELAB width warnings. `cordic_pipline.v:30-43` resets x/y but not `rot_out`, causing its reset-priority synthesis warning and possible unknown angle after reset.

`canny_get_grandient.v:192-205` attempts four one-hot direction flags using truncated `angle_out`, a `<<2` comparison, and `type_d[8]`. `type` is the XOR of sign bits (`:159-168`), delayed by a fixed 9-bit register, while magnitude and angle take different CORDIC taps. There is no verified common pixel identity among direction, magnitude, sign, and delayed controls. `start` is declared (`:63`) but is a combinational expression dependent on the other flags (`:192-198`), making the direction logic non-obvious and potentially circular in interpretation. For this RTL's Sobel signs, equal nonzero signs mean a `\\`-oriented gradient in image coordinates; opposite signs mean `/`. The old code maps `type=1` to `path_fou` (`\\`) and `type=0` to `path_two` (`/`), the opposite mapping (`:192-198`; NMS mapping `canny_nonLocalMaxValue.v:73-91`). This must be corrected and ideal-angle tested, not copied blindly.

The old `gra_path` is 16 bits: `[15:14]` class, `[13:10]` one-hot direction, `[9:0]` magnitude (`canny_get_grandient.v:207-220`). Threshold comparisons use the wider `sqrt_out_n` with fixed strict `>100` and `>50`, then store only `sqrt_out_n[9:0]`, so magnitudes of 1024+ can wrap to small stored values before NMS. NMS compares only those 10-bit fields (`canny_nonLocalMaxValue.v:73-91`). The original threshold/hysteresis module receives only the resulting 2-bit class and performs a single 3×3 strong-neighbor promotion; it is unchanged in this phase (`canny_doubleThreshold.v:57-92`).

The matrix generator delays video controls through two registers (`matrix_generate_3x3.v:36-75`). Sobel partial sums and absolute/sign arithmetic add two registered stages (`canny_get_grandient.v:111-149`), but the old fixed 9-bit sign delay (`:159-168`) and 11-bit video-control shift (`:223-244`) have no explicit derivation against the mismatched CORDIC stage taps. Phase 4 must replace these with one documented iteration count and aligned registered control/sign pipelines. The public top-level 8-bit grayscale interface must stay unchanged.
