# Phase 5 pipeline specification (from active Phase 4B RTL)

Scope: 8-bit grayscale stream at `canny_edge_detect_phase4b_top.per_img_y` to 1-bit `post_img_bit`. The historical RGB-to-Y converter is not in the synthesis hierarchy (`rtl/phase4b/canny_edge_detect_phase4b_top.v:2-50`). No Phase 4B RTL is changed in Phase 5.

## Stage order and arithmetic

1. **Gaussian** — `image_gaussian_filter` uses a `matrix_generate_3x3(DATA_WIDTH=8, DATA_DEPTH=640)` window. Row sums are registered as unsigned 12-bit values, then accumulated in a 12-bit register; output is `sum_gray >> 4`, truncated to 8 bits. The kernel is `[1 2 1; 2 4 2; 1 2 1]`, divisor 16, with floor truncation (not rounding). See `rtl/baseline/vip_gaussian_filter.v:43-65,71-90,112-118`. With 8-bit inputs the maximum sum is 4080, fitting 12 bits.
2. **Sobel** — a second 8-bit 3×3 matrix feeds four unsigned 10-bit weighted sums: left=`p11+2p21+p31`, right=`p13+2p23+p33`, top=`p11+2p12+p13`, bottom=`p31+2p32+p33`. Each is at most 1020. `abs_gx=|left-right|`, `abs_gy=|top-bottom|` are unsigned 11-bit; sign flags mean nonnegative when the first side is greater than or equal to the second. This means signed `Gx=left-right`, `Gy=top-bottom`. See `rtl/phase4b/canny_get_gradient_phase4b.v:29-49`.
3. **CORDIC** — 16 registered vectoring iterations in signed 26-bit Q12 x/y, using arithmetic right shifts and the integer Q16-degree atan table. Its final x is multiplied by signed 48-bit constant 39797 (inverse gain in Q16), then arithmetic-shifted by 28 and clamped to unsigned 11 bits. The direction is one-hot: 1 horizontal, 2 slash, 4 vertical, 8 backslash. First-quadrant boundaries are 22.5° and 67.5° in Q16 degrees; opposite Sobel signs select slash versus backslash. Phase 4B adds two post-CORDIC registers, for total block latency 18 clocks. Zero-vector direction is horizontal. See `rtl/phase4b/cordic_gradient_phase4b.v:2-35,37-60,62-170`. The bit-accurate arithmetic is already tested by `model/cordic_reference.py:15-54`.
4. **Fixed threshold classification** — after the CORDIC output, magnitude **strictly greater than 100** becomes class 2 (strong), **strictly greater than 50** becomes class 1 (weak), otherwise packed path zero. The 17-bit packed path is `{class[1:0], direction[3:0], magnitude[10:0]}`; low-class pixels lose both direction and magnitude. See `rtl/phase4b/canny_get_gradient_phase4b.v:65-79`.
5. **NMS** — a third 17-bit 3×3 matrix selects neighbors using the **center's one-hot direction**. Horizontal compares center to left/right; slash to upper-right/lower-left; vertical to up/down; backslash to upper-left/lower-right. Both comparisons are strict `>`; equal magnitudes are suppressed. It outputs the center's two-bit threshold class or zero, not magnitude. See `rtl/phase4/canny_nonLocalMaxValue_phase4.v:13-40`.
6. **Local promotion** — a fourth 2-bit 3×3 matrix computes `search=OR(strong bit of all nine cells)`, including center, and `high_low=OR(two class bits of center)`. Output is `high_low && search` registered. Thus a weak center survives only if any immediate 8-neighbor is strong; a strong center survives via itself. This is **one-pass local weak-edge promotion**, not recursive connected hysteresis. See `rtl/baseline/canny_doubleThreshold.v:65-96`.

## Stream/window behavior (important border semantics)

`matrix_generate_3x3` delays vsync/href/clken by two registers and updates its nine window registers only when delayed href **and** delayed clken are high. It clears the window registers whenever delayed href is low; it does not perform explicit image-coordinate padding (`rtl/baseline/matrix_generate_3x3.v:44-99`). Consequently the first two columns of each active line contain zeroed/partial horizontal history, not reflected or replicated pixels. The last two columns are not given special padding; the implementation emits one valid sample per input pixel.

Vertical taps come from `one_column_ram`: current delayed pixel, first 640-entry RAM output, second 640-entry RAM output. Both RAMs initialize to zero, use independent circular read/write pointers without frame reset, and advance only under their respective enables. The RAM read is registered, and the write path is delayed two clocks (`rtl/baseline/one_column_ram.v:21-67`, `rtl/baseline/fifo_ram.v:17-65`). Therefore startup top rows begin from initialized zero memory, while later frames can inherit vertical history from the preceding frame; **it is not per-frame zero padding**. The exact first/last row and pixel-coordinate association must be established by the Phase 5 cycle-level reference and RTL stage comparison, not assumed from a textbook convolution. No arbitrary post-hoc spatial shift is permitted.

Phase 5 experimentally established that association. The verification stream uses 640 active pixels per line, 24 blank clocks between lines, and 128 blank clocks after the last line. The Python line-buffer/register model matches **every Gaussian sample** in ten consecutive 640×16 frames and two consecutive 640×480 frames (`results/phase5/small_comparison.json`, `results/phase5/full_comparison.json`). At each stage, the nth valid output corresponds to the nth active input coordinate in the protocol; data is delayed in clock time, but there is no arbitrary software image shift.

Measured examples from `reports/phase5_border_observations.txt`: for a white frame following a black frame, Gaussian output at (x=0,y=0) is 15, (1,0) is 47, (2,0) is 63, (2,1) is 191, and (2,2) is 255. This is the causal zero/partial history at the left and initially empty upper rows. The rightmost output (639,2) is 255: no right-side padding cycle is synthesized. The following impulse frame is black near (100,0), yet its Gaussian output there is **191**, and at (100,1) it is **63**, because the non-reset RAMs retain the preceding white frame's last two rows. Only by row 2 does that background become zero. The bottom rows are emitted without future-row padding; the 3×3 windows represent current and two earlier stream rows, not a centered look-ahead convolution.

All stage arithmetic is unconditional on pixel-valid once the registers are out of reset; control signals travel on parallel registered paths. Golden-model comparisons must sample only `clken && href` at the rising clock edge and must track vsync/frame boundaries.
